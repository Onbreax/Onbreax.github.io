Connecter les alertes Gmail à Matchwork

Version 1.1.6 · Vérifié le 18 octobre 2026.

Chaque profil Matchwork peut être associé à son propre compte Gmail. La connexion de Gmail dans ChatGPT est distincte de celle de l’application.

Le code est prêt. Avant le premier accès réel, le projet Google doit être configuré par son propriétaire. Aucun mot de passe Gmail ni secret client n’est à mettre dans Matchwork.

1. Un projet Google pour l’application

  1. Ouvre la console Google Cloud avec le compte qui administrera ce projet. Crée un projet, par exemple « Matchwork personnel ».
  2. Dans « API et services » → « Bibliothèque », active Gmail API.
  3. Dans « Google Auth platform », configure l’application : nom Matchwork, adresse de contact et audience Externe pour un compte Gmail personnel. Si le projet reste en mode test, ajoute les comptes qui utiliseront Matchwork dans les utilisateurs de test.
  4. Dans « Accès aux données », ajoute la permission https://www.googleapis.com/auth/gmail.readonly. Cette permission permet la lecture de la boîte ; la sélection des alertes par expéditeur se fait ensuite dans Matchwork.

Google classe cette permission comme restreinte. Des exceptions à la vérification existent pour un usage personnel ou un petit groupe connu. Un écran d’application non vérifiée peut apparaître : vérifie qu’il s’agit bien de ton propre projet avant d’autoriser l’accès.

2. Pour l’APK Android

  1. Dans « Clients », crée un client OAuth de type Android.
  2. Renseigne le package fr.onbreax.matchwork.
  3. Renseigne l’empreinte SHA-1 du certificat de l’APK :
    12:3F:AD:C1:A3:36:21:E0:BD:1E:BF:CD:29:94:ED:8E:9C:4A:D5:79.
  4. Enregistre le client. Aucun identifiant ni secret Android n’est à recopier dans l’application.
  5. Dans Matchwork, ouvre le profil voulu → Profil et cible → Alertes emploi Gmail → Connecter Gmail. Choisis le compte Google et autorise la lecture.

La connexion utilise les services Google Play et leur fenêtre d’autorisation officielle. Cette version garde le certificat de signature des précédents APK Matchwork.

3. Pour le navigateur

  1. Dans le même projet, crée un second client OAuth, de type Application Web.
  2. Dans les origines JavaScript autorisées, ajoute exactement https://onbreax.github.io, sans chemin ni barre finale.
  3. Copie l’identifiant client se terminant par .apps.googleusercontent.com.
  4. Ouvre la version web hébergée de Matchwork. Dans le profil, déplie « Configuration Google (une fois) », colle cet identifiant dans « Identifiant client OAuth Web », puis enregistre.
  5. Clique sur Connecter Gmail et autorise l’accès. Si le navigateur bloque la fenêtre Google, autorise les fenêtres de connexion pour ce site puis relance.

Le fichier HTML téléchargé reste utilisable pour les autres fonctions. La connexion Google requiert la version hébergée et une origine autorisée. Les autorisations déjà données permettent de renouveler l’accès ; le navigateur peut néanmoins demander une nouvelle fenêtre de connexion après expiration du jeton.

4. Antériorité et rythme

Par défaut : 30 derniers jours et à chaque recherche. La période est réglable à 7, 30, 90, 180 ou 365 jours. La source peut aussi être limitée à une récupération par jour lors d’une recherche, ou être utilisée manuellement. Aucune récupération programmée n’est lancée lorsque l’application est fermée.

« Lancer la recherche » inclut les alertes Gmail activées avant les autres sources. « Récupérer les alertes » n’utilise que Gmail et n’effectue aucune analyse IA. Chaque lot traite au plus deux pages de 100 emails ; si d’autres restent à traiter, « Continuer la récupération » reprend le lot suivant. Les emails déjà traités ne sont pas relus.

5. Informations importées et limites

La recherche cible jobalerts-noreply@linkedin.com sur la période choisie. Les offres présentes dans ces emails sont importées, avec dédoublonnage par identifiant LinkedIn puis par intitulé, employeur et lieu. Les exclusions configurées dans la recherche s’appliquent aussi. Une alerte peut contenir des suggestions éloignées des mots-clés initiaux.

Les emails contiennent parfois seulement un intitulé, un employeur et une ville. Ces offres portent la mention « annonce partielle » ; leur date de réception n’est pas présentée comme leur date de publication, et leur disponibilité reste indéterminée. L’import des alertes ne débloque pas les pages LinkedIn. Une analyse IA éventuelle reste provisoire et utilise les crédits OpenRouter selon les options déjà choisies.

Les liens de suivi personnalisés sont remplacés par le lien canonique de l’offre. Les jetons Gmail restent en mémoire et ne sont pas inclus dans les sauvegardes. L’application n’envoie, ne modifie ni ne supprime d’email. Dissocier un profil conserve ses offres ; cela ne révoque pas les autorisations d’autres profils utilisant le même compte. Pour retirer l’accès Google, utilise la page des autorisations Google.

En cas de refus de connexion

Vérifie que l’API Gmail est activée, que le compte figure parmi les utilisateurs de test si nécessaire, et que le type de client correspond à la plateforme. Sur Android, contrôle le package et le SHA-1 ; sur le web, contrôle l’origine et l’identifiant client. Un message d’erreur reste visible dans le profil. Les offres déjà enregistrées sont conservées.

Sources de configuration

  • Google, Gmail API — démarrage JavaScript.
  • Android Developers, Autoriser l’accès aux données Google.
  • Google, Permissions Gmail et filtrage des messages.
  • Google, Vérification OAuth et exceptions pour usage personnel.

Tests automatisés des imports et des profils réalisés. L’autorisation Google réelle et l’usage sur un téléphone physique restent à vérifier après la configuration du projet.
